# AmneziaWG-панель — развёртывание для OwnNetBot

Панель `AlexisHW/amneziawg-web-ui` для линейки «Amnezia WG» с каскадом
через российский релей.

## Инфраструктура

| Роль | Сервер | Адрес | Домен |
|---|---|---|---|
| Бот и сайт | VPS-1, Beget SPB | `217.114.2.219` | `своясеть.рокфактор.рф` |
| **Панель + WireGuard** | Грузия | `144.31.246.234` | `ge01awg.rockfactor.ru` |
| **Каскад** | 1Gb.ru, Москва | `81.177.48.224` | `on.rockfactor.ru` |

```
   клиент ──UDP 51821──→ [ каскад MSK ] ──DNAT──→ [ панель GE :51820 ]
                          on.rockfactor.ru         ge01awg.rockfactor.ru
                                                          │
   админ ──WG──→ 10.10.0.0/24 ────────→ [ nginx 443 ] ────┤
                                                          │
   бот ──TLS через интернет────────────→ 217.114.2.219 ───┘
```

## Отличие от PasarGuard: панель закрывается целиком

У PasarGuard путь `/sub/` обязан быть публичным — клиенты открывают ссылку
со своих устройств. У AmneziaWG этого нет: конфигурация приходит файлом
в Telegram, а подключение идёт по UDP напрямую к WireGuard. **В веб-панель
клиенты не обращаются никогда.**

Поэтому вайтлист вешается на весь сервер: только публичный IP VPS-1
и админский туннель. Разделение по путям не нужно.

Basic Auth панели при этом остаётся включённым как второй рубеж — автор
проекта прямо предупреждает в README, что одного Basic Auth недостаточно
и он подбирается перебором.

## Шаг 1. Базовая настройка сервера панели

```bash
ssh root@144.31.246.234

apt-get update && apt-get upgrade -y
apt-get install -y ufw curl git nginx certbot
mkdir -p /var/www/certbot

ufw default deny incoming
ufw default allow outgoing
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
```

**Порт WireGuard открываем только каскаду.** Все конфигурации будут указывать
на релей, значит, прямые подключения не нужны:

```bash
ufw allow from 81.177.48.224 to any port 51820 proto udp
```

Компромисс: релей становится единственной точкой входа, и его недоступность
отключит всех клиентов. Если хочешь запасной прямой путь, открой порт всем
(`ufw allow 51820/udp`) и держи вторую версию конфигурации без каскада.

Docker:

```bash
curl -fsSL https://get.docker.com | sh
```

## Шаг 2. Админский WireGuard

Тот же скрипт, что для PasarGuard:

```bash
cd /tmp
git clone https://github.com/rockfactor/onbot_site.git onbot
cd onbot/deploy/panels/pasarguard
sudo bash setup-admin-wg.sh
```

**Важно: на вопрос о порте укажи `51900`, а не значение по умолчанию.**
Панель публикует диапазон `51820–51830/udp` под клиентские интерфейсы,
и админский туннель на `51830` столкнётся с ним.

```bash
ufw allow 51900/udp
ufw --force enable
```

Конфигурация для телефона:

```bash
sudo qrencode -t ansiutf8 < /etc/wireguard/clients/device2.conf
```

## Шаг 3. Запуск панели

```bash
PANEL_PASS="$(openssl rand -base64 32)"
echo "Пароль панели: $PANEL_PASS"   # сохранить в менеджер паролей

docker run -d \
  --name awg-panel \
  --restart unless-stopped \
  -e NGINX_USER=api_bot \
  -e NGINX_PASSWORD="$PANEL_PASS" \
  -e AUTO_START_SERVERS=true \
  -e DEFAULT_MTU=1280 \
  --cap-add NET_ADMIN --cap-add SYS_MODULE \
  -p 127.0.0.1:8080:80 \
  -p 51820-51830:51820-51830/udp \
  -v awg_config:/app/config \
  alexishw/amneziawg-web-ui:1.8.5
```

Разбор ключевых решений:

**`-p 127.0.0.1:8080:80`** — панель доступна только с самого сервера.
Наружу её выставляет наш nginx, он же ограничивает доступ. Без привязки
к loopback порт был бы открыт в обход вайтлиста.

**`SSL_EMAIL` и `SSL_DOMAIN` не задаём.** Встроенный certbot панели занял бы
порт 80 и подрался с нашим nginx. TLS терминируем снаружи.

**`IP_LIST` не используем.** Вайтлист внутри контейнера видит адреса через
Docker-сеть, а не реальные источники. Ограничение на уровне хоста надёжнее
и проверяемо.

**Тег `:1.8.5` зафиксирован.** У репозитория нет файла LICENSE — см. раздел
про лицензию ниже.

Проверка:

```bash
docker ps
ss -tlnp | grep 8080     # должно быть 127.0.0.1:8080, не 0.0.0.0:8080
curl -su api_bot:"$PANEL_PASS" http://127.0.0.1:8080/api/servers
```

    -d ge01awg.rockfactor.ru --email ВАШ_EMAIL --agree-tos --non-interactive

## Шаг 5. Создание сервера AWG в панели

Подключись к админскому WireGuard, открой `https://ge01awg.rockfactor.ru/`,
войди под `api_bot` и созданным паролем.

Создай сервер: порт `51820`, подсеть `10.0.0.0/24`, MTU `1280`, обфускация
включена.

Параметры обфускации генерируются модулем `vpn_api/awg_obfuscation.py` —
он проверяет ограничения протокола до отправки в панель:

```bash
python -c "
from vpn_api.awg_obfuscation import generate_server_params, packet_sizes
p = generate_server_params()
print(p.as_dict())
print(packet_sizes(p))
"
```

Затем узнай идентификатор сервера — он понадобится боту:

```bash
curl -su api_bot:ПАРОЛЬ https://ge01awg.rockfactor.ru/api/servers | python3 -m json.tool
```

Значение поля `id` пойдёт в `AWG_SERVER_ID`.

### Мультисервер

Панель умеет держать несколько интерфейсов в одном контейнере. Тарифы
1/3/5 устройств можно развести по разным подсетям и портам — но тогда
на каскаде понадобится отдельное правило DNAT под каждый порт. На старте
проще один сервер.

## Шаг 6. Каскад

На релее `81.177.48.224`:

```bash
wget -O install.sh https://raw.githubusercontent.com/anten-ka/kaskad/main/install.sh
chmod +x install.sh && ./install.sh
```

В меню: протокол UDP, целевой IP `144.31.246.234`, порт входа `51821`,
порт выхода `51820`.

Скрипт создаёт правила `DNAT` в `PREROUTING` и `MASQUERADE` в `POSTROUTING`.
Дополнительного туннеля нет — это ядерный NAT, поэтому **MTU не меняется**,
в отличие от схемы «WireGuard поверх WireGuard». Подбирать MTU не придётся.

Проверка, что правила на месте:

```bash
iptables -t nat -S PREROUTING | grep 51821
iptables -t nat -S POSTROUTING | grep MASQUERADE
```

### Что нужно знать про эту схему

**Панель перестанет видеть реальные IP клиентов.** MASQUERADE подменяет
источник, и в статистике все подключения придут с адреса релея. На выдачу
конфигураций это не влияет, но диагностика «кто именно подключён»
и обнаружение злоупотреблений усложняются.

**Релей не может читать трафик** — через него идёт уже зашифрованный
WireGuard. Компрометация каскадного сервера не раскрывает содержимое
соединений, в отличие от компрометации панели.

**Канал релея — потолок для всего сервиса.** Весь клиентский трафик идёт
через него, и его пропускная способность ограничивает всех.

**`PersistentKeepalive` обязателен.** Каскад держит состояние в conntrack,
запись для UDP протухает за пару минут без трафика. Значение 25 секунд
в конфигурации это закрывает — проверь, что панель его проставляет.

**Осторожно с пунктом «полный сброс» в меню `kaskad`.** Он ставит политики
`INPUT`, `FORWARD` и `OUTPUT` в `ACCEPT`, то есть полностью открывает
файрвол. После сброса заново поднимай `ufw`.

## Шаг 7. Подключение к боту

В `/opt/ownnetbot/.env` на VPS-1:

```bash
AWG_API_URL=https://ge01awg.rockfactor.ru
AWG_API_USER=api_bot
AWG_API_PASSWORD=<пароль из шага 3>
AWG_SERVER_ID=<id из шага 5>
```

Панель работает на HTTP Basic Auth, а не на API-ключе — для `aiohttp`
это `auth=aiohttp.BasicAuth(user, password)`.

Приватной сети с Грузией нет, поэтому запросы идут через интернет.
Защищает их TLS, а доступ ограничен вайтлистом по публичному IP VPS-1.

Проверка:

```bash
curl -su api_bot:ПАРОЛЬ https://ge01awg.rockfactor.ru/api/servers
```

### Автоподмена Endpoint

Панель генерирует `.conf` с адресом самого сервера — `144.31.246.234:51820`.
Клиенту нужен адрес релея. Вручную это править не надо: подмену делает
адаптер при выдаче.

В таблице `vpn_nodes` у ноды заполняется поле:

```
client_endpoint = 'on.rockfactor.ru:51821'
```

`AmneziaWGAdapter` получает конфигурацию одним запросом
`POST /api/servers/{sid}/clients` и переписывает строку `Endpoint`
**только внутри секции `[Peer]`** — в `[Interface]` лежат параметры
обфускации, трогать их нельзя. Если `Endpoint` не найден или найден дважды,
адаптер падает с ошибкой: лучше не выдать конфигурацию, чем выдать сломанную.

Добавление второго релея — строка в БД, без правок кода. Замена
заблокированного — обновление одного поля.

Стоит также проверить `GET /api/system/refresh-ip`: если панель позволяет
задать произвольный публичный адрес вместо автоопределения, каскад можно
прописать прямо там. Подмена в адаптере всё равно нужна — на случай,
когда одна панель обслуживает несколько релеев.

## Обфускация: что хранить и как менять

### Разделение параметров

| Группа | Параметры | Можно ли менять |
|---|---|---|
| Общие | `S1`–`S4`, `H1`–`H4` | **нет**, после выдачи первого конфига |
| Клиентские | `Jc`, `Jmin`, `Jmax` | да, генерируются на каждую выдачу |

Общие параметры участвуют в разборе рукопожатия: расхождение хотя бы
в одном значении между сервером и клиентом — соединение не устанавливается.
Клиентские управляют мусорными пакетами до рукопожатия, сервер их игнорирует,
поэтому у каждого клиента может быть свой профиль. Именно это мешает
построить одно правило DPI на весь сервис.

Сгенерированные `ServerParams` сохраняются в `vpn_nodes` рядом
с `client_endpoint` — чтобы знать, какой интерфейс какими значениями настроен,
и уметь воспроизвести конфигурацию при восстановлении.

### Ротация без обрыва

Менять `S1`–`S4` и `H1`–`H4` на работающем интерфейсе нельзя: все ранее
выданные клиенты отвалятся разом.

Если DPI начнёт распознавать текущий профиль, порядок такой:

1. Создать новый интерфейс `awg1` со свежими параметрами через мультисервер
   панели — на другом порту и в другой подсети.
2. Добавить правило DNAT на каскаде под новый порт.
3. Переключить выдачу новых клиентов на `awg1` — в `vpn_nodes` пометить
   `awg0` неактивным для новых выдач, но оставить работающим.
4. Дождаться истечения подписок на `awg0`.
5. Удалить `awg0` и его правило на каскаде.

Так замена проходит постепенно, без единовременного отключения всех.

## Проверка изоляции

С постороннего хоста — не с VPS-1 и не из-под WireGuard:

```bash
curl -m 5 -o /dev/null -w 'панель      %{http_code}\n' https://ge01awg.rockfactor.ru/
curl -m 5 -o /dev/null -w 'API         %{http_code}\n' https://ge01awg.rockfactor.ru/api/servers
curl -m 5 -o /dev/null -w 'порт 8080   %{http_code}\n' http://144.31.246.234:8080/
```

| Проверка | Ожидание |
|---|---|
| панель, API | `403` |
| порт 8080 | таймаут |
| форма входа | не должна появляться |

Если видишь окно Basic Auth — вайтлист не работает. Разбираться до того,
как заводить клиентов.

С VPS-1 те же запросы должны отдавать `401` без учётных данных
и `200` с ними.

## Обслуживание

### Бэкапы

**Состояние панели хранится в JSON-файле, не в базе.** Том с конфигурацией
обязательно включать в резервное копирование — его потеря означает, что все
выданные ключи перестают работать.

```bash
# Полный экспорт через API
curl -su api_bot:ПАРОЛЬ https://ge01awg.rockfactor.ru/api/config/export \
     > /root/awg_backup_$(date +%F).json

# Плюс сам том Docker
docker run --rm -v awg_config:/data -v /root:/backup alpine \
    tar czf /backup/awg_volume_$(date +%F).tar.gz /data
```

Поставь в cron и выгружай копии в S3.

### Обновление

Тег зафиксирован намеренно. Перед обновлением сделай бэкап и меняй версию
осознанно:

```bash
docker pull alexishw/amneziawg-web-ui:НОВАЯ_ВЕРСИЯ
docker stop awg-panel && docker rm awg-panel
# повторить docker run с новым тегом
```

После обновления проверь, что порт по-прежнему привязан к `127.0.0.1`.

### Особенности панели

Из CHANGELOG 1.7.1: снятие `suspend_at` **не реактивирует клиента
автоматически** — это сделано намеренно. После продления подписки всегда
вызывай `POST .../activate` явно, иначе клиент останется заблокированным.

Помесячной статистики трафика по клиенту нет, есть только текущие счётчики
пиров. Для биллинга по трафику пришлось бы снимать
`GET /api/servers/{sid}/traffic` по крону и складывать дельты в Postgres.
